# 4. AI 및 데이터 처리 방식

본 서비스는 초등 교실 경제활동 시뮬레이션에서 학생의 **신용등급을 작성**하고, 학급 단위 **경제이벤트(정책) 제안의 근거 데이터**를 산출한다. AI 서버(`credit-ai`)는 교실 경제 DB(`fin_edu`)의 생활·거래 기록을 피처로 변환한 뒤, 학습된 딥러닝 모델과 학급 집계 로직으로 결과를 만든다.

---

## 4.1 AI가 수행하는 역할

AI는 생성형 챗봇이 아니라, **교실 경제 데이터를 점수·지표·설명 문장으로 바꾸는 평가·진단 엔진**이다. 역할은 두 갈래다.

### 4.1.1 개인 신용등급 작성

학생 한 명의 소비 습관과 성실 지표를 보고 신용점수·등급·리포트를 만든다.

| 단계 | 역할 | 구현 |
| --- | --- | --- |
| 피처 추출 | 거래·급여·출결·숙제 원천 데이터를 모델 입력 3개로 정규화한다. | `features/extract.py` |
| 점수 추론 | `CreditMLP`(64-32-16, GELU, LayerNorm)가 비선형 관계를 반영해 300~1000점을 출력한다. | `model/network.py`, `model/scorer.py` |
| 등급 부여 | 점수를 최우수(A+) · 우수(A) · 양호(B) · 보통(C) · 노력(D)로 구간화한다. | `grade_for()` |
| 기여도 설명 | 각 피처를 이상치로 바꿨을 때 점수가 얼마나 오르는지(`score_lift`)를 계산한다. | `model/explain.py` |
| 리포트 작성 | 초등학생 눈높이의 요약 문장과 습관 개선 추천(최대 3건)을 만든다. | `reports/copy.py` |
| 저장 | 회원당 최신 리포트 1건을 `ai_report`에 upsert한다. | `reports/writer.py` |

모델이 학습하는 관계는 다음과 같다.

- 출결률·숙제 완료율이 높을수록 가점, 둘이 함께 높으면 시너지 가점
- 과소비(`spending_trend`가 1에 가까움)일수록 감점, 숙제를 미룬 상태에서 과소비하면 추가 감점
- 출결이 매우 낮으면 기본 신뢰 감점

학습 라벨이 아직 없으므로, 위 규칙을 담은 교사 함수(`teacher_score`)로 합성 데이터 8,000건을 만들어 MLP를 학습한다. 산출물은 `models/credit_mlp.pt`, `models/scaler.json`이다. 실제 라벨이 쌓이면 같은 학습 진입점만 바꿔 재학습한다.

### 4.1.2 학급 경제지표 산출과 경제이벤트 제안 기반 제공

학급 전체의 화폐·소비·저축·격차를 시점 스냅샷으로 남겨, 교사가 경제이벤트(정책)를 고를 근거를 만든다.

| 단계 | 역할 | 구현 |
| --- | --- | --- |
| 학급 묶기 | `member.class` 문자열(예: `3-1`)을 `class_id`(예: 301)로 바꾸고 학생을 학급 단위로 묶는다. | `metrics/compute.py`, `metrics/refresh.py` |
| 지표 계산 | 총화폐량, 1인당 자산·소비, 주간 거래량, 소비·거래 변화율, 저축률, 빈부격차(지니)를 계산한다. | `compute_class_metric()` |
| 스냅샷 저장 | 계산 결과를 `economic_metric`에 insert한다. 과거 시점과 비교할 수 있게 덮어쓰지 않는다. | `credit-ai metrics` |
| 이벤트 근거 | 저장된 지표는 학급 경제 진단과 정책·이벤트 제안의 입력으로 쓰인다. | 백엔드 정책 제안 API가 최신 스냅샷을 조회 |

이 레포지토리는 이벤트 문장 자체를 생성하지 않고, **이벤트를 제안하는 데 필요한 학급 경제 상태 벡터를 만든다.** 개인 단위 행동 제안(과소비 줄이기, 숙제 끝내기, 출석 지키기)은 신용평가 리포트의 추천 문장으로 함께 제공한다.

## 4.2 사용 데이터

### 4.2.1 원천 데이터 (교실 경제 DB)

배포 모드(`APP_MODE=db`)에서는 MySQL `fin_edu`를 읽는다. 로컬 오프라인 모드는 데모 학급(3-2반 20명)으로 동일 파이프라인을 검증한다.

| 테이블 | 사용하는 컬럼 | 용도 |
| --- | --- | --- |
| `member` | `id`, `name`, `role`, `class`, `job`, `salary`, `cs_attendance`, `cs_homework` | 학생 식별, 학급 구분, 급여 보조값, 출결·숙제 피처. `role=teacher`는 제외 |
| `account` | `id`, `member_id`, `account_type`, `balance` | 지출 추이·학급 자산·저축·대출 구분 |
| `transaction` | `id`, `account_id`, `amount`, `description`, `occured_at` | 수입·지출 판별, 소비 기울기, 주간 거래량 |
| `payroll` | `member_id`, `transaction_id` | 급여 거래를 수입으로 고정 |

참고로 `member.cs_overdue`(도서 연체)와 세금 컬럼(`tax1_*`~`tax5_*`)은 스키마에 있으나 **현재 모델 입력에는 넣지 않는다.**

계좌 유형은 다음처럼 정규화한다.

| 정규화 값 | 판별 | 지표에서의 취급 |
| --- | --- | --- |
| `CHECKING` | 기본 입출금 | 소비·거래량에 포함, 자산에 포함 |
| `SAVING` | `SAVING`, `DEPOSIT`, 적금/예금/저축 | 자산·저축률에 포함, 소비에서는 제외 |
| `LOAN` | `LOAN`, `DEBT`, `CREDIT`, 대출 | 총화폐량·자산에서 제외 |

수입 거래는 `payroll.transaction_id`이거나 적요에 `급여`, `월급`, `봉급`, `salary`, `payroll`, `income`, `용돈`이 들어간 건이다.

### 4.2.2 학습·추론 산출물

| 데이터 | 위치 | 설명 |
| --- | --- | --- |
| 합성 학습셋 | `training/synthetic.py` | 교사 함수가 붙인 피처–점수 쌍. 기본 8,000건, 검증 MAE 약 13.8점 |
| 모델 가중치 | `models/credit_mlp.pt` | 학습된 MLP |
| 스케일러 | `models/scaler.json` | 피처별 평균·표준편차, hidden `[64, 32, 16]` |
| 신용 리포트 | `ai_report` | 회원당 1건. 점수, 요약, 추천 본문, 기대효과, 피처 JSON |
| 학급 지표 | `economic_metric` | 학급·시점별 스냅샷. `(class_id, measured_at)` 인덱스 |

## 4.3 입력·출력 데이터

### 4.3.1 신용등급 작성

#### 모델 입력 피처

원천 데이터를 아래 3개 실수(각 0~1)로 압축한 뒤 StandardScaler로 정규화해 MLP에 넣는다.

| 피처 | JSON 키 | 의미 | 산출 방식 |
| --- | --- | --- | --- |
| 지출 추이 | `spending_trend` | 0=검소, 1=과소비 | 지출/수입 비율(최대 2배까지 본 뒤 0~1로 축소) + 최근 지출 기울기. 수입이 없으면 `member.salary`를 쓰고, 그것도 없으면 0.45 |
| 숙제 완료율 | `homework_rate` | 높을수록 성실 | `member.cs_homework` (없으면 1.0) |
| 출결률 | `attendance_rate` | 높을수록 신뢰 | `member.cs_attendance` (없으면 1.0) |

직접 채점 API(`POST /v1/score`)는 위 3개만 JSON으로 받는다. 회원 채점 API(`POST /v1/score/member/{id}`, `POST /v1/score/class`)는 DB에서 피처를 추출한다.

#### 출력

| 항목 | 필드 | 범위·형식 | 저장 |
| --- | --- | --- | --- |
| 신용점수 | `credit_score` | 정수 300~1000 | `ai_report.credit_score` |
| 등급명 | `grade` | 최우수 / 우수 / 양호 / 보통 / 노력 | API만 |
| 등급코드 | `grade_code` | A+ / A / B / C / D | API만 |
| 사용 피처 | `features` | `{spending_trend, homework_rate, attendance_rate}` | `ai_report.features` (JSON) |
| 피처 기여도 | `contributions` | 피처별 현재값·이상값·`score_lift`·방향 | API만. DB 미저장 |
| 요약 | `summary` | 초등 문장, 최대 512자 | `ai_report.summary` |
| 추천 | `recommendations[]` | `recommendation_type`, `content`, `expected_effect` 1~3건 | 본문·기대효과를 줄바꿈으로 합쳐 `ai_report.content`, `ai_report.expected_effect` |

등급 구간은 다음과 같다.

| 점수 | 등급 | 코드 |
| --- | --- | --- |
| 900 이상 | 최우수 | A+ |
| 800 이상 | 우수 | A |
| 700 이상 | 양호 | B |
| 600 이상 | 보통 | C |
| 600 미만 | 노력 | D |

추천 유형은 기여도(`direction=improve`이고 `score_lift ≥ 8`)가 큰 피처 순으로 고른다.

| `recommendation_type` | 조건 | 학생에게 보이는 내용 |
| --- | --- | --- |
| `REDUCE_SPENDING` | 지출 추이를 낮추면 점수가 오름 | 필요한 것과 사고 싶은 것을 나누고 일주일 용돈을 계획하기 |
| `FINISH_HOMEWORK` | 숙제 완료율을 높이면 점수가 오름 | 숙제를 그날그날 끝내기 |
| `ATTEND_CLASS` | 출결률을 높이면 점수가 오름 | 학교에 꾸준히 나오기 |
| `KEEP_HABIT` | 개선 여지가 거의 없음 | 지금 습관을 유지하기 |

이상 피처(설명용)는 지출 추이 0.18, 숙제 1.0, 출결 1.0이다.

#### 입력·출력 예시

입력 (직접 채점)

```json
{
  "spending_trend": 0.20,
  "homework_rate": 0.95,
  "attendance_rate": 0.98
}
```

출력 (회원 채점, 필드 발췌)

```json
{
  "member_id": 1,
  "name": "민준",
  "class_name": "3-2",
  "job": "은행원",
  "credit_score": 820,
  "grade": "우수",
  "grade_code": "A",
  "features": {
    "spending_trend": 0.2,
    "homework_rate": 0.95,
    "attendance_rate": 0.98
  },
  "summary": "민준 친구의 신용점수는 820점, 등급은 우수입니다. 약속을 잘 지키고 돈을 알뜰하게 다루고 있어요.",
  "recommendations": [
    {
      "recommendation_type": "KEEP_HABIT",
      "content": "지금 습관을 그대로 유지해 보세요. 작은 약속을 계속 지키는 것이 가장 좋은 신용 관리입니다.",
      "expected_effect": "현재 등급을 안정적으로 유지할 수 있습니다."
    }
  ]
}
```

### 4.3.2 학급 경제지표 · 경제이벤트 근거

#### 입력

학급에 속한 학생들의 `account`, `transaction`, `payroll` 전체와 측정 시각(`as_of`, 기본값 현재 시각)이다. CLI `uv run credit-ai metrics`가 전 학급을 한 번에 계산한다.

주간 창은 `[as_of - 7일, as_of)`, 직전 주는 `[as_of - 14일, as_of - 7일)`이다.

#### 출력 (`economic_metric`)

| 항목 | 컬럼 | 타입 | 산출 |
| --- | --- | --- | --- |
| 학급 식별자 | `class_id` | int | `member.class`를 정수화. `3-1` → 301 |
| 학급 총화폐량 | `total_money` | int | 대출 계좌를 뺀 잔액 합 |
| 1인당 평균 자산 | `average_asset` | decimal(12,2) | `total_money / 학생 수` |
| 주간 거래량 | `weekly_transaction_volume` | int | 최근 7일 거래 절댓값 합 |
| 1인당 평균 소비 | `average_consumption` | decimal(12,2) | 입출금 계좌의 비수입 거래 절댓값 합 / 학생 수 |
| 소비 변화율 | `consumption_change_rate` | decimal(8,4) | (이번 주 소비 − 지난 주 소비) / 지난 주 소비 |
| 거래 변화율 | `transaction_change_rate` | decimal(8,4) | (이번 주 거래량 − 지난 주 거래량) / 지난 주 거래량 |
| 저축률 | `saving_rate` | decimal(8,4) | 주간 수입이 있으면 `(수입 − 소비) / 수입`, 없으면 `저축잔액 / 총화폐량` |
| 빈부격차 | `wealth_gap` | decimal(8,4) | 학생별 자산의 지니계수 (0~1) |
| 측정 시각 | `measured_at` | datetime | 스냅샷 시각 |

변화율의 직전 주 값이 0이면, 이번 주도 0이면 0, 아니면 +1.0으로 둔다.

이 스냅샷이 경제이벤트 제안의 입력이다. 예를 들어 소비 변화율이 높으면 과소비 억제 이벤트, 저축률이 낮으면 저축 캠페인, 빈부격차가 크면 나눔·재분배 이벤트를 고르는 근거가 된다.

## 4.4 처리 흐름

```text
[교실 경제 DB]                    [AI 서버 credit-ai]
 member / account /               ┌─ 신용등급 작성 ─────────────────┐
 transaction / payroll ──────────►│ 피처 추출 → MLP 추론 → 등급     │
                                  │ → 기여도 설명 → 요약·추천 문장  │
                                  │ → ai_report upsert              │
                                  └─────────────────────────────────┘
                                  ┌─ 경제이벤트 근거 ───────────────┐
                                  │ 학급 묶기 → 주간 창 집계        │
                                  │ → economic_metric insert        │
                                  └─────────────────────────────────┘
                                              │
                                              ▼
                                  [백엔드] 리포트 조회 / 학급 정책·이벤트 제안
                                              │
                                              ▼
                                  [프론트] 학생 신용등급, 교사 학급 경제 화면
```

외부 인터페이스는 다음과 같다.

| 구분 | 경로·명령 | 입력 | 출력 |
| --- | --- | --- | --- |
| 즉시 채점 | `POST /v1/score` | 피처 3개 | 점수·등급·리포트 (미저장) |
| 학생 채점 | `POST /v1/score/member/{id}` | `member_id` | 리포트, DB 모드면 `ai_report` 저장 |
| 학급 일괄 채점 | `POST /v1/score/class` | 없음 | 학생별 리포트 목록 |
| 학급 순위 | `GET /v1/class` | 없음 | 점수 내림차순 명단 |
| 경제지표 갱신 | `uv run credit-ai metrics` | DB 전체 학생 | `economic_metric` 스냅샷 목록 |
